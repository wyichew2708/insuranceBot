# v2.9 — customer-reported conversation fixes

## Changes

- Product-level comparison no longer requires tier selection first. It cites
  published topics and provides product links and follow-up questions; exact
  numeric comparisons still require known tiers. “Compare it with Travel
  Infinite” can use Tiq Travel from the preceding conversation. A generic
  comparison request asks for the products instead of being treated as off-topic.
- “Introduce your travel products” uses the catalogue; “introduce Tiq Travel”
  uses the product overview. Neither should retrieve unrelated home benefits.
- Both HTTP endpoints now distinguish omitted history from explicitly empty
  history. Previously the request model's default empty list disabled server
  memory even when the caller omitted history. The chat uses server memory
  when enabled and a bounded client history otherwise. Its session id survives
  reload within the tab; New chat explicitly starts a fresh session.
- Long verified replies have an extractive preview, with complete paragraphs
  or bullet items, plus an expandable full answer and conditions. The API keeps
  the full verified answer and exposes `preview` separately. Explicit full-detail
  requests bypass the preview. No new facts are generated by summarisation.
- Purchase-after-flight-cancellation and already-overseas purchase questions
  select relevant published travel conditions before generic intent routing.
  These answers explicitly scope the rule to the product whose document was
  read and do not decide the individual's claim. A different named product
  cannot inherit Tiq's wording.
- “Cancellation policy” selects the customer-cancellation section where it
  exists, instead of automatic termination. The source heading is retained
  in the reply, so the existing answerability gate can recognise the subject.
  The gate's acceptance rules were not relaxed.

## Validation

Regression tests exercise both HTTP endpoints after seven intervening turns,
explicit empty-history overrides, catalogue and named-product introductions,
comparisons with and without context, short previews, both reported travel
situations, and the opposite purchase sequence.

Browser checks verified the concise introduction and expansion control,
product retention after reload, full-answer expansion, an explicit New chat
reset that drops the previous product, and a contextual comparison with product links
and follow-up buttons. Existing untracked `okf-real/**/plain.md` files were not
edited or included in these changes.

The initial full conversation run remained 1678/1711, zero gained and zero lost
against the pushed v2.9 baseline. A further affected-case run covers cancellation,
renewal, comparison and introduction after the final section-selection changes:
177/180, with zero gained and zero lost. The final full unit suite passes
1035 tests with three skipped. Ruff lint/format, Mypy and diff whitespace checks pass.
Detailed local reports are under `.eval-reports/v2.9-customer-fixes/` and
`.eval-reports/v2.9-customer-affected-final.json`.

Limitations: previews preserve the full answer rather than replacing it;
comparison detail remains bounded by the published corpus; situation detection
is deterministic and currently handles the implemented purchase-timing patterns.
The broader v2.9 tool integrations and benefit graph remain separate work.
